# Selvendran & Asmitha Wedding Invitation

A local React + Vite + Tailwind CSS wedding invitation. The supplied intro video is preserved unchanged. One optional 60-second background-music excerpt has a small play/pause control.

## Run Locally

Requires Node.js 20.19+ or 22.12+ and npm.

```sh
npm install
npm run dev
```

Open the Local URL printed by Vite, normally http://localhost:5173. Vite uses another available port when 5173 is occupied.

```sh
npm run build
npm run preview
npm test
```

The build is written to `dist/`. This project does not automatically publish or deploy.

VS Code Live Server can also serve the invitation: run `npm run build`, then open the project root or `dist/index.html` with Live Server. The root automatically opens the compiled invitation. Run the build again after source edits; use Vite for automatic updates while editing. Build assets use relative paths, so `dist/` can be served from a subdirectory.

## Background Music

`assets/wedding-background-music-timed.m4a` retains the original timestamps of the user-supplied `vidssave.com Vazhithunaiye (Instrumental - Violin) 240P.mp4`. Its first 20 seconds are silent, playback is cued once to source 00:20, and the file ends at source 01:20. Only the selected 60-second passage is heard. Audio is reduced to 25% amplitude, with a two-second fade-in at 00:20 and a three-second fade-out from 01:17 to 01:20, encoded for consistent mobile playback. `music.start` and `music.end` declare the source boundaries. The supplied source file and original intro film are not modified. There is no YouTube iframe, external music service, player panel or added section.

Music is on by default: the persistent player attempts playback immediately on mount, alongside the automatically starting muted film, with no entry button. The film never waits for audio permission, buffering or output startup. If the browser blocks audible autoplay, the next trusted tap or key press anywhere retries it automatically; the small header toggle also starts it directly. Ordinary interactions never override a guest's deliberate pause. The unchanged film is 12.6 seconds long; when sound autoplay is allowed, uninterrupted audio is approximately at source 00:32.6 when it ends. The existing ended-driven transition and opening reveals remain independent of music. Skip to invitation still bypasses the intro, without rewinding music already in progress.

One header music control remains available during the intro and the invitation. `musicEnabled` starts as `true` on every fresh opening, and the persistent audio element explicitly starts with `muted = false`. This is the requested setting, not proof of playback: the button shows ON only after the native `playing` event or a successful `play()` promise. Loading, blocked autoplay and playback errors leave it OFF, with a play/retry action. The first click while playback is blocked explicitly calls `audio.play()` instead of muting an already silent player. Once playing, the button mutes and pauses, then unmutes and resumes from the exact saved position. No stored music preference is restored. It controls the same persistent audio element, outside the page's inert intro wrapper. Muting music never pauses or restarts the film. Scrolling, phase changes, video failures and React re-renders do not stop or re-create the player. To keep music playing throughout the invitation, source 00:20-01:20 repeats with the existing gentle fades instead of stopping or disabling the toggle. Only the segment boundary seeks back to 00:20; the file's silent lead-in is never replayed. Unmounting removes listeners and pauses playback.
